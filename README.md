# NIR Lab · Patient Timeline Viewer — מדריך שימוש

פלטפורמה אינטרנטית לצפייה בנתוני בדיקות של מטופלים לאורך זמן. כל מטופל מוצג כציר זמן
אינטראקטיבי שבו כל בדיקה (Lab Data, ביופסיות, מדדים אפיגנטיים) היא "מסלול" (track) נפרד,
עם אפשרות להשוואה, שכבות (overlays) ותובנות מבוססות מתאם בין בדיקות.

**האתר החי:** https://dvir-drori.github.io/interactive_DB_viewer/

כל האפליקציה היא קובץ סטטי יחיד (`docs/index.html`) הרץ בדפדפן — אין צורך בשרת. הנתונים
נטענים מ‑`docs/config.json` ומקבצי ה‑bedGraph שלצידו.

---

## הפעלה מהירה

- **אונליין:** פשוט פותחים את הקישור לאתר החי למעלה.
- **מקומית:** מריצים שרת סטטי בתיקיית `docs/` (כי הדפדפן חוסם `fetch` מקבצים מקומיים):

  ```bash
  cd docs
  python3 -m http.server 8000
  # ואז נכנסים ל: http://localhost:8000/index.html
  ```

## מדריך שימוש

### בחירת מטופל — חיפוש חופשי
במקום רשימה נפתחת ארוכה, שדה החיפוש בראש המסך (**Patient**) מאפשר להקליד ולסנן. אפשר
לחפש לפי מזהה מטופל (למשל `TRN0785`) או לפי סוג איבר (למשל `liver`). בוחרים בעזרת העכבר
או בעזרת המקלדת (חצים מעלה/מטה ו‑Enter; `Esc` לסגירה). לצד כל תוצאה מוצג מידע קצר (איבר,
ותיוג `uploaded` למטופלים שהועלו ידנית).

### ציר הזמן (X-axis)
- **עיגון לרשומה הראשונה:** ציר הזמן של כל מטופל מתחיל מהתאריך המוקדם ביותר שלו
  (**First record**). אין תלות בתאריך ההשתלה — הוא אינו אינפורמטיבי לכל המטופלים ואינו
  קיים לכולם. זהו גם התיקון לבאג שבו הוצגו תאריכים שגויים (למשל 2027).
- **מצב תצוגה (`X-axis`):**
  - `Calendar date` — תאריכים אמיתיים בלוח השנה (ברירת מחדל).
  - `Days since first record` — מספר ימים מאז הרשומה הראשונה (0, 30, 60, …), שימושי
    להשוואת מטופלים על ציר אחיד.
- **סמן השתלה (`Transplant marker`):** מסומן כברירת מחדל כבוי. כשמפעילים אותו, מוצג קו
  מקווקו ותווית במיקום תאריך ההשתלה — רק למטופלים שעבורם הוא ידוע.

### מסלולים (Tracks) — הסרגל הצדדי
המסלולים מקובצים לפי קטגוריה (Lab Data, Biopsies, Epigenetic, ו‑Uploaded לנתונים שהועלו).
לכל מסלול:
- **הפעלה/כיבוי** בעזרת תיבת הסימון. אפשר להפעיל/לכבות קטגוריה שלמה מהכותרת שלה, או
  להשתמש ב‑**All / None**.
- **צבע** — בורר צבע ייעודי.
- **סוג תצוגה** — `Line+Dot`, `Dots`, `Bars`, `Area`, `Step`.
- **סדר** — גרירה בעזרת הידית (☰) משנה את סדר תת‑הגרפים.
- **שם** — לחיצה כפולה על שם המסלול מאפשרת לשנותו.

מסלולים ללא נתונים עבור המטופל הנבחר מוסתרים אוטומטית. ביופסיות מוצגות תמיד כסמני
מעוין (diamond).

### שכבות (Overlays) — השוואה על גרף אחד
מיזוג כמה מסלולים לתת‑גרף אחד לצורך השוואה ישירה:
1. מסמנים את תיבת ה‑**ovl** ליד שני מסלולים או יותר (מופיעה במעבר עכבר על שורת המסלול).
2. לוחצים **Create Overlay** בתחתית הסרגל.
3. אפשר ליצור **מספר שכבות שונות** במקביל (למשל קבוצה אחת של אנזימי כבד וקבוצה שנייה
   של תפקודי כליה) — כל קבוצה מקבלת תת‑גרף משלה.
4. **התאמת קנה מידה חכמה:** אם כל המסלולים בשכבה חולקים יחידות (למשל ALT + AST, שניהם
   U/L) — הם מוצגים על ציר Y אמיתי משותף. אם היחידות שונות (למשל CREATININE ב‑mg/dL מול
   ALT ב‑U/L) — כל מסלול מנורמל לטווח 0–1 כדי שהמגמות יהיו ניתנות להשוואה, בעוד הערכים
   האמיתיים נשמרים ב‑tooltip.
5. הסרה: ✕ על תגית הקבוצה מפצל אותה, או **Split All** לפיצול הכול.

### סינון לפי תאריכים
שדות **From / To** בסרגל הכלים מגבילים את חלון הזמן המוצג. **Apply** להחלה, **Reset**
לביטול.

### תובנות מתאם (Insights)
כפתור **◧ Insights** פותח ניתוח מתאם בין הבדיקות של המטופל הנבחר:
- **איך זה מחושב:** לכל זוג בדיקות, הערכים מיושרים על רשת ימים משותפת (אינטרפולציה
  ליניארית) בחלון החפיפה ביניהן, ואז מחושב מקדם המתאם.
- **שיטה (`Method`):** `Pearson` (מתאם ליניארי) או `Spearman` (מתאם מונוטוני מבוסס דירוג).
- **חפיפה מינימלית (`Min overlap`):** מספר ימי החפיפה המינימלי הנדרש כדי לחשב זוג;
  זוגות מתחת לסף מדולגים.
- **תצוגה:** מפת חום (heatmap) של כל הזוגות (ירוק = מתאם חיובי, אדום = שלילי), ולצידה
  רשימות מדורגות של המתאמים החיוביים והשליליים החזקים ביותר עם `r` ו‑`n` (גודל המדגם).
- **פרשנות:** מתאם אינו סיבתיות. ערכי `n` נמוכים או חלונות זמן קצרים מפחיתים מהימנות.

### העלאת נתונים (בדפדפן, ללא שרת)
- **+ bedGraph** — העלאת קבצי `.bedGraph`/`.bg`.
- **+ CSV** — העלאת קובץ `.csv` עם העמודות `PatientID`, `Date`, `Label`, `Value`
  (תאריכים בפורמט `DD/MM/YYYY` או `YYYY-MM-DD`). מטופלים חדשים מעוגנים לתאריך המוקדם
  ביותר שלהם.
- אפשר גם לגרור קבצים לאזור הגרף.

### שמירה וטעינה של סשן
המצב (מטופל נבחר, מסלולים, צבעים, שכבות, טווח תאריכים, מצב ציר, ועוד) נשמר אוטומטית
בדפדפן. **Save** מייצא סשן לקובץ JSON, ו‑**Load** מייבא אותו בחזרה.

## מבנה הנתונים והפקה מחדש

- `docs/config.json` — רשימת המטופלים, המסלולים והקטגוריות. לכל מטופל: `referenceDate`
  (= `firstDate`, תאריך הרשומה הראשונה — נקודת העיגון של הציר), ובאופן אופציונלי
  `transplantDate` ומטא‑דאטה (`organ`, `birthYear`).
- `docs/bedgraphs_by_label/*.bedGraph` — קובץ לכל בדיקה. כל שורה: `PatientID`, היסט‑יום
  (day offset מהרשומה הראשונה), וערך.
- `docs/annotations.gff` — התאריך האמיתי של כל נקודה (משמש לשחזור `firstDate`).

### הפקת config.json מחדש
כדי ש‑ציר הזמן יציג תאריכים נכונים, `referenceDate` חייב להיות תאריך הרשומה הראשונה של
המטופל (ולא תאריך ההשתלה). הסקריפט הבא בונה את `config.json` נכון — הוא כולל את **כל**
המטופלים שיש להם נתונים, ומשחזר את `firstDate` במדויק מתוך `annotations.gff`:

```bash
python3 docs/build_config.py
```

הסקריפט מושך גם תאריכי השתלה ומטא‑דאטה מ‑`docs/transplant_dates.csv` כשקיימים.

## רכיב ה‑backend (אופציונלי)

התיקייה `nir_lab/` מכילה גרסת full‑stack (React + FastAPI) לניהול הנתונים והפקת קבצי
ה‑IGV/bedGraph מבסיס נתונים. היא אינה נדרשת להפעלת הצפייה — האתר הסטטי ב‑`docs/` עומד
בפני עצמו. פרטים נוספים ב‑`nir_lab/README.md`.
